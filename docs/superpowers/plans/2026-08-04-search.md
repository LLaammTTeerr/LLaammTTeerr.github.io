# Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a reader find a post by what it is about, and jump straight to a record by pasting its hash, height or address — the last interactive surface the spec names, and the last unbuilt thing on the site.

**Architecture:** A build-time JSON index served as a static file, fetched lazily the first time the search box is focused. No server, no search dependency: §8 says *"a build-time JSON index, lazy-loaded on first focus of the search box. No server and no heavy dependency; the corpus is tens to hundreds of posts."*

**Tech Stack:** Astro island, existing `chain-data.ts`. No new runtime dependencies.

## Global Constraints

- **§9: a page load touches no third party.** The index is same-origin. A test scans every emitted script for absolute *and protocol-relative* URLs — it caught `//example.com/beacon.js` on the last branch, so do not expect to slip past it.
- **No module under `src/site/` may read the clock.** Two consecutive builds must be byte-identical — an index whose key order or field order varies between runs breaks that.
- **Sealed blocks are frozen**; `chain.lock.json` is never rewritten.
- **Every displayed field must be committed, or re-derived from something committed.** A search result showing a stale title after an amendment is the same defect this project has fixed at six surfaces.
- **No hard-coded colours** — eleven reader-selectable palettes; a test scans the whole stylesheet.
- **Explorer chrome is English; author-facing content is Vietnamese.**
- **Zero dead links and every `src` resolves.**
- `noUncheckedIndexedAccess: true`; `npm run typecheck` runs `tsc --noEmit && astro check`.
- `npm test` — 958 passing plus 3 skips, green **both** with the demo corpus seeded (its current state) and after `npm run demo:clear`. Re-seed if a task clears it.

## What the spec requires

- §8: build-time JSON index, **lazy-loaded on first focus**, no heavy dependency.
- §9: the search box lives in the **nav row** — "identity, section links, search, preferences" — not in a separate band.
- §6: *"Pasting a full `0x…` transaction hash into the search box resolves to its post."*
- §3.9: *"Amendments are listed in block transaction tables but **excluded from post lists, RSS, and the search index** — they are ledger entries, not new writing."*

### Task 1: The index

**Files:**
- Create: `src/pages/search-index.json.ts`, `src/site/search-index.ts`
- Test: `tests/site/search-index.test.ts`

**What goes in it.** Enough to find a post and to resolve a pasted identifier, and no more — every byte is downloaded by a reader who uses the box. At minimum: posts (title, slug, tags, series, date, transaction hash), plus whatever is needed to resolve a hash, a block height and an address to its page.

**Post entries must carry the governing state**, not the sealed original. `ResolvedPost` exists for exactly this; a search result showing a superseded title would be the seventh occurrence of one defect on this project.

**Amendments are excluded** (§3.9). They are ledger entries, not writing, and a reader searching for a post should not get two hits for one post.

**Do not include post bodies.** The corpus is small now and will not stay small; body text would dominate the payload. If title, tags and series prove too thin in practice, that is a later decision made with evidence, not a guess made now. Say in your report what a reader cannot find as a result.

### Task 2: The search box

**Files:**
- Create: `src/components/Search.astro`, `src/styles/search.css`
- Modify: `src/layouts/Base.astro`
- Test: `tests/site/search.test.ts`

**Behaviour:**

- Lives in the **nav row** (§9), on every page.
- **Fetches the index on first focus, once.** Not on page load — that would put a download in front of every reader for a feature most will not use. Not on every focus either.
- **A pasted `0x…` hash resolves to its post** (§6). Extend the same courtesy to a block height and an address, since a reader who has just used `/verify` will have hashes in their clipboard and this is an explorer.
- **Keyboard-usable**: type, arrow through results, Enter to open, Escape to dismiss. A search box that requires a mouse is broken for the people most likely to use it.
- **Without JavaScript** it must not render a dead control. Either omit it or disable it with a reason, the way `/verify` explains itself. Decide and say which.
- **A search that finds nothing must say so**, not render an empty void.

- [ ] **Step 1: Write the failing tests** — the box is present on more than one page; nothing is fetched before first focus; a known title finds its post; a pasted hash resolves; an unknown query reports no results; the no-JS path is honest.
- [ ] **Step 2: Run and confirm failure.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Drive it in a real browser** — type, arrow, Enter; paste a hash from `/chain.json`; confirm with devtools that the index is fetched **once, on first focus, and not before**. Paste the evidence.
- [ ] **Step 5: Run the suite seeded and cleared, verify zero dead links, then commit** — `feat(site): add search`

## Self-Review

**Spec coverage.** §8's build-time lazy-loaded index (Task 1, fetched by Task 2), §9's placement in the nav row (Task 2), §6's hash resolution (Task 2), §3.9's exclusion of amendments (Task 1).

**What this plan does not do.** No fuzzy matching, no ranking model, no search dependency — §8 rules those out at this corpus size, and a heavier design should be justified by a reader failing to find something, not anticipated.

**Carried debt this plan does not close.** `summary` is still hashed nowhere; if a search result shows it, it must not sit where a reader would read it as committed. `/address/lamter.eth` remains unbuilt though §6 names it.

**Risk flagged for both implementers.** Every serious defect on this project was found by driving the real workflow end to end, and none by the suite passing. For search specifically: a box that renders and does nothing will pass a great many tests. Type into it in a real browser before calling it done.
